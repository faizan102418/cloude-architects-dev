FREQUENTLY ASKED QUESTIONS

DevOps Architecture & FAQs

Key insights into the engineering decisions and workflows behind Cloud Architects.

Every deploy creates a timestamped folder inside /var/www/TEAM/releases/. Once files are staged, version stamped, and verified, an atomic Linux symlink swap points /var/www/TEAM/current to the new release instantly, ensuring web visitors never see half-updated files.
Our check.yml workflow runs check-site.sh on an Ubuntu runner. It audits every HTML file for mandatory <title> tags, verifies that all internal href and src links point to real files, and ensures no asset exceeds the 1MB limit.
If an incident occurs, the Pipeline Engineer triggers rollback.yml directly from GitHub Actions. The script inspects deploys.log, identifies the previous stable release, re-points the current symlink in under 5 seconds, and notifies the team via Slack.
The Slack webhook URL is kept exclusively as a secured GitHub Actions secret (SLACK_WEBHOOK_URL) and never committed to the Git repository. The runner posts rich JSON payloads with commit hashes, author IDs, and status badges directly to the #cloud-alerts channel.
